# 5～7 分钟演示脚本

## 0:00～0:40：问题和边界

用一句话介绍：这是一个面向零售经营分析的企业数据 Copilot，Java 管身份、租户、任务、审批和审计，Python 管 RAG、NL2SQL 与安全工作流；模型永远不能直接执行任意代码或绕过只读数据库。

## 0:40～1:30：架构

打开 README 架构图，指出浏览器只能访问 Java、内部调用带服务 token 与 `traceparent`、PostgreSQL 保存最终状态、Redis 只保存短期进度。

## 1:30～3:20：三个问题

1. “2025 年每季度的净销售额是多少？”展示规划轨迹、引用、SQL、表格与折线/柱状图。
2. “销售额最高的五个客户是谁？”展示 join、聚合、LIMIT 和结果表。
3. “销售额的指标口径是什么？”展示指标知识引用；随后问一个资料中没有的问题，展示证据不足时拒答。

每个问题都指出 SQL 是只读的，结果含引用和 trace id。截图应来自同一次已记录的演示环境，并保存到 `docs/evidence/`。

## 3:20～4:20：安全和审批

提交“删除所有订单”，展示请求在模型和执行器前被拒绝。再展示低置信度/受控敏感列进入一次性审批，以及同一审批不能重复决策。

## 4:20～5:20：恢复与可观测性

断开并重新连接 SSE，展示 `Last-Event-ID` 续传。打开 Prometheus，查看 Java HTTP P95、Agent 节点延迟、Token 和 SQL 拒绝数，并用同一 trace id 串联 Java/Python。

## 5:20～6:20：评测

打开 P10 报告：55 条 NL2SQL、20 条危险请求、24 条 RAG；强调离线 Gold Replay 与真实模型评测的区别，不把离线 100% 宣称为模型准确率。

## 6:20～7:00：工程取舍

说明三个 ADR：Java/Python 分离、不执行任意代码、混合检索。最后说明当前限制：Northwind 单数据集、真实模型批量报告需显式运行、公网部署与录屏属于发布动作而非仓库验收。
