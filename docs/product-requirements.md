# 产品需求：零售经营分析 Copilot

## 1. 产品定义

Enterprise Data Copilot 是供中小型零售企业内部使用的数据分析助手。它让不了解 SQL、也不熟悉数据库表结构的业务分析员，通过自然语言获得遵循统一指标口径、可核验且可审计的经营分析结果。

首版只解决 Northwind 数据模型上的零售经营分析问题，不以“万能数据分析 Agent”为目标。Chinook 仅用于验证数据源和 schema 适配能力，不作为主评测集。

## 2. 目标用户

| 角色 | 主要目标 | 首版权限 |
|---|---|---|
| 业务分析员（核心用户） | 查询销售趋势、定位变化原因、比较客户/商品表现 | 提交问题、查看自己的结果与执行轨迹 |
| 数据管理员 | 维护数据源和指标定义，处理高风险审批 | 管理租户内数据源、文档、审批和审计 |
| 只读查看者 | 消费已经完成的分析结果 | 查看被授权的结果，不创建任务 |

## 3. 三个核心问题

1. **趋势是什么？** 按年、季度或月查看销售额、订单数、客单价等指标及同比/环比。
2. **变化为什么发生？** 从区域、客户、商品、品类等有限维度分解增减贡献，并明确区分事实与推断。
3. **谁表现最好或最差？** 在明确时间范围和指标口径后，对客户、商品或品类进行排名与占比分析。

## 4. 用户价值

- 无需理解表名、连接关系和 SQL 语法即可提出经营问题。
- 每个结论都能回溯到指标定义、生成 SQL 和结果数据。
- 危险、越权、敏感或成本不可控的查询在执行前被阻止或进入审批。
- 失败不是黑盒：用户能看到稳定的错误原因和下一步建议。

## 5. MVP 范围

### 包含

- 单租户演示链路，但数据模型和接口从第一天显式携带租户身份。
- 一个 Northwind PostgreSQL 只读数据源。
- 指标定义和 schema 元数据检索。
- 自然语言到只读 SQL、AST 安全校验、超时、LIMIT 和结果大小限制。
- 文字答案、结果表格以及 line/bar/pie 三类结构化图表规范。
- 查询历史、Agent 步骤、错误与审计记录。
- 至少 50 条 Northwind NL2SQL 评测题和 20 条指标检索题。

### 不包含

- 对业务数据库执行 INSERT、UPDATE、DELETE、DDL、COPY 或存储过程。
- 跨租户或跨未授权 schema 查询。
- 自由执行模型生成的 Python、Shell 或 JavaScript。
- 任意公网数据库接入、多 Agent 自由协作、多数据库方言承诺。
- 在工作流正确性得到证明前引入 Kafka、Kubernetes 或复杂管理大屏。

## 6. 必须拒绝或暂停的情况

系统应在执行数据库查询之前采用确定性规则做最终裁决：

- 任何写入、删除、DDL、COPY、多语句或不能可靠解析的 SQL：拒绝。
- 访问非 allowlist 表、系统 schema、敏感列或其他租户资源：拒绝或按策略申请审批。
- 无时间范围的大表扫描、笛卡尔积、递归查询或 EXPLAIN 成本超过阈值：请求缩小范围或进入审批。
- 用户要求忽略规则、泄露提示词/凭据/DSN 或执行任意代码：拒绝。
- 指标口径缺失、检索证据不足或问题有关键歧义：先澄清，不编造答案。
- 查询结果不能支持因果结论：只描述相关性和数据中可观察到的贡献，不声称因果关系。

具体示例见 [手工验收问题与拒绝场景](manual-acceptance.md)。

## 7. 关键用户流程

1. 管理员登记一个受 allowlist 约束的只读 PostgreSQL 数据源并测试连接。
2. 管理员上传带版本与章节信息的指标说明文档。
3. 分析员选择数据源、输入经营问题并创建分析任务。
4. Java 平台校验登录、角色、租户和幂等键，保存任务后调用内部 Python API。
5. Python Agent 检索指标与相关 schema，生成分析计划和 SQL。
6. SQL guard 解析 AST、检查权限与成本；需要时拒绝、澄清或暂停等待审批。
7. 只读执行器运行通过校验的查询，校验和截断结果。
8. 系统返回答案、SQL、表格、图表规范、引用和步骤轨迹，并记录审计事件。

## 8. 成功指标与验收门槛

首个可演示 MVP 应至少满足：

- 危险查询集阻断率 100%，且任何危险 SQL 均未到达业务数据库执行接口。
- 50 条 Northwind 评测题有可复现的 execution accuracy 基线；不预先虚构目标数值。
- 指标检索报告 Recall@5、MRR、引用命中率和拒答正确率。
- 每个成功任务可关联用户、租户、SQL、引用、步骤状态和 trace ID。
- 每个失败任务返回稳定错误码，不泄露密钥、完整 DSN、堆栈或大段业务数据。
- README 中只写实际测得的成功率、延迟和成本。

## 9. P0 退出条件

- 产品名称和场景不再以“通用 Agent”表述。
- 主数据集、角色、核心问题、拒绝策略和非目标已记录。
- Java/Python 的所有权、信任边界和失败责任已通过 ADR 固化。
- 10 条正常验收问题和 10 条拒绝/暂停场景可作为后续回归测试种子。
- 团队成员可以在 60 秒内说明：Java 保护企业业务边界，Python 实现可替换的 AI 分析工作流，SQL 是否可执行由确定性防线最终决定。
