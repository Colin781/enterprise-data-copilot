# P12 作品集收尾与项目交接

## 仓库内完成项

- README 包含 30 秒介绍、架构图、请求时序、安全边界、启动方式、评测表、三个演示问题、限制和灵感来源。
- 三份 ADR 覆盖 Java/Python 边界、不执行任意代码和混合检索。
- P1～P11 阶段文档、P10 评测报告、P11 性能报告、演示脚本和简历证据均可追溯。
- `make verify-p12` 自动检查关键文档、数据集数量、报告字段、Docker/负载资产和 README 必须章节。
- `make verify-all` 是 P1～P12 的统一本地验收入口。

## 发布型交付

以下项目需要仓库之外的账号或人工动作，因此保留为发布清单，不能伪装成自动完成：

1. 选择云平台，配置域名、TLS、Secret Manager、日志保留和预算告警。
2. 使用 `docker-compose.full.yml` 或等价平台部署，并用只读 Northwind 数据源验证。
3. 按 `docs/demo-script.md` 录制 5～7 分钟视频。
4. 在成功运行真实问题后，把三个 UI 截图放入 `docs/evidence/`；截图不得使用错误页或伪造数字。
5. 把最终提交/PR/CI 链接补到求职材料；Issue/Project 看板应在实际使用的平台创建。

## 完成定义

项目代码在 P12 后进入维护状态：修复缺陷、依赖安全更新和真实模型回归可以继续，但不再扩展 Kafka、Kubernetes、多数据库方言或任意代码执行，除非有新的目标与 ADR。
